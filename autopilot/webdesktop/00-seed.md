- 원문 (2026-11-23): "웹앱 기반에서 원격데스크탑 및 VPN까지 제공되는 프로그램 만들고 싶어 현재 PC에 Jump to desktop 과 tailscale을 합쳐진 솔루션으로 RUST 기반으로 새롭게 기능을 구현한 웹앱이었으면 좋겠어 Window PC <-> Mac book <-> iPhone <-> Android 간 호환이 자유로웠으면 좋겠어 지금의 경우는 설정이 번거롭다고 느껴서 안쓰게 되는거 같거든 위에 언급한 두 프로그램 REA와 github에 원격데스크탑과 vpn 관련 데이터 딥 리서치 진행부터 하자"
- 서비스 유형: 복합 — 네트워크(메시 VPN) + 실시간 미디어(원격 데스크톱) + 웹 UI + 기기별 네이티브 에이전트
- 주 도메인 / 인접 도메인: 원격 접속(원격 데스크톱·메시 VPN) / NAT 통과·실시간 영상 코덱·기기 인증·OS 권한(화면 녹화·접근성·VPN 권한)
- 감지된 제약:
  - Rust 기반 구현
  - "웹앱" 형태
  - Windows · macOS · iOS · Android 서로 접속
  - 설정이 쉬워야 함 (지금 두 제품을 안 쓰게 된 이유가 설정 번거로움)
- 로드할 블라인드스팟 프로파일: 보안 민감(원격 제어·네트워크 접근) · 멀티 플랫폼 클라이언트 · 실시간 미디어
- 강도: full — 사유: 원격 제어·네트워크 접근은 보안 사고 시 피해가 큼, 4개 OS, 외부 시스템(중계 서버·앱스토어) 2개 이상
- 해석한 것 (사용자가 말하지 않았는데 내가 정한 것 — 틀리면 비싼 순):
  1. Assumed: 첫 사용자는 본인 1인(개인 기기 여러 대). 팀·회사 판매는 아님 — 확장 해석이므로 A2 질문 후보.
  2. Assumed: "웹앱" = 조작 화면(기기 목록·접속 버튼·원격 화면 보기)이 브라우저/PWA. 기기에 까는 작은 에이전트는 필요(브라우저만으로는 VPN·화면 제어가 불가능할 수 있음 — A1에서 확인).
  3. Assumed: "Jump Desktop + Tailscale 합침" = 한 번 로그인하면 내 기기들이 자동으로 서로 보이고(메시 VPN), 그 위에서 원격 화면을 바로 연다.
  4. Assumed: 중계·조정 서버는 본인이 직접 운영(자체 호스팅) 가능해야 함. 상용 SaaS 운영은 범위 밖.
  5. Assumed: iPhone·Android는 주로 "접속하는 쪽". 휴대폰을 원격 제어 "당하는 쪽"은 OS 제약 확인 후 결정.
